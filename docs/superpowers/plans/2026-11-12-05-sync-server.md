# SSHCraft Teilplan 5: Sync-Server Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ein selbst betreibbarer Sync-Server `sshcraft-server`, der Konten, Geräteprotokolle, Bereiche, Schlüsselumschläge und verschlüsselte Datensätze speichert und live verteilt, ohne je etwas davon lesen zu können, mit SQLite als Standard und PostgreSQL als Wahl, Verwaltung per Befehl und einem Docker-Image.

**Architecture:** Ein neues Crate `crates/sshcraft-server` mit Bibliothek (Router, Zustand, Speicher) und Programm (Befehle `serve`, `users`, `devices`, `api-key`). Die HTTP-Schicht (axum) prüft Zugang, Rechte und Versionen und reicht alles Weitere an einen `Store`-Trait, den ein SQLite- und ein PostgreSQL-Backend gleich erfüllen; beide laufen gegen dieselbe Vertragstest-Suite. Alle Prüfungen der Protokollobjekte kommen aus `sshcraft-proto` (Geräteprotokoll, Zertifikate, Manifeste, Anmelde-Signatur), der Server erfindet keine eigenen. Push läuft über eine WebSocket-Verbindung je Gerät, die nur meldet, dass sich etwas geändert hat; die Daten holt der Client über HTTP.

**Tech Stack:** Rust 1.99 (Edition 2024), axum 0.8.9 (Feature `ws`), tokio 1.54.1, rusqlite 0.42.0 (bundled, wie im Kern), tokio-postgres 0.7.18 mit deadpool-postgres 0.14.2, clap 4.6.7 (Features `derive`, `env`), tracing 0.1.44, tracing-subscriber 0.3.23 (Feature `env-filter`), subtle 2.6.1, async-trait, sha2, data-encoding, rand, serde, serde_json, uuid, thiserror; Tests mit tower 0.5.3 (`ServiceExt::oneshot`), http-body-util 0.1.5, tokio-tungstenite 0.30.0, tempfile.

**Spec:** `docs/superpowers/specs/2026-11-11-sshcraft-design.md`, Abschnitte 3 (Server: Rust), 6 (Zugang, Konto, Anmelden, Geräte und Geräte-Sperre, E-Mail), 7 (Sync, Angreifermodell, Live und offline), 8 (Teilen, nur die Rechte, die der Server durchsetzt) und 12 (Server-Verwaltung); dazu `docs/protocol.md` und der Fahrplan `docs/superpowers/plans/2026-11-11-sshcraft-roadmap.md`.

## Global Constraints

- Alle Regeln der Teilpläne 1 bis 4 gelten weiter: Arbeitsbaum unter `G:\Claude\worktrees`, Code Englisch, Commits Deutsch ohne KI-Zuschreibung und ohne Gedankenstriche, UTF-8, neueste stabile Paketversionen, Gegenproben für Regeln, Rechte und Datenwege.
- **Der Server kann nichts entschlüsseln** und bekommt nie einen privaten Schlüssel. Er speichert Protokollobjekte als JSON, so wie `sshcraft-proto` sie serialisiert, und liest daraus nur die Kopfdaten.
- **Keine eigene Prüflogik für Protokollobjekte:** Geräteprotokoll mit `DeviceLog::verify`, Anmeldung mit `DeviceCertificate::verify_auth`, Manifeste mit `AreaManifest::verify`. Was der Server zusätzlich prüft, sind Zugang, Rollen, Versionen und Größen.
- **[Claudes Entscheidung] SQLite über `rusqlite`, nicht über `sqlx`:** `sqlx` 0.9.0 verlangt `libsqlite3-sys` unter 0.38, `rusqlite` 0.42.0 im Kern nutzt 0.40; zwei Fassungen einer Bibliothek mit `links = "sqlite3"` lassen sich in einem Workspace nicht bauen. PostgreSQL deshalb über `tokio-postgres` mit `deadpool-postgres`.
- Fehlerantworten immer als JSON `{"code": "<snake_case>", "detail": "<optional>"}`, bei Versionskonflikten zusätzlich `"current": <u64>`. Codes und HTTP-Status stehen in Task 1; der Client (Teilplan 6) übersetzt sie, der Server liefert nie Sätze für Menschen.
- **Nie loggen:** Sitzungs-Token, API-Key (Ausnahme: einmal beim ersten Start, damit der Betreiber ihn sieht), Anfrage- und Antwortkörper.
- Zeit kommt aus `AppState::now()` (Unix-Sekunden `i64`), damit Tests sie stellen können.
- Programm- und API-Texte Englisch (internationales Publikum, wie `docs/protocol.md`).
- Binäre Felder in JSON und in URL-Pfaden als Base64 URL ohne Polsterung (`data_encoding::BASE64URL_NOPAD`), wie im Protokoll.

## Review Focus

1. **Zwei Geräte schreiben gleichzeitig** denselben Datensatz, dasselbe Manifest oder hängen gleichzeitig an dasselbe Geräteprotokoll an: genau einer gewinnt, der andere bekommt `409 conflict` mit dem aktuellen Stand, auf beiden Backends. Tests in Task 2 und 3 (parallel gestartete Schreibvorgänge).
2. **Gültiges Sitzungs-Token, aber das Gerät ist inzwischen gesperrt** (über das Geräteprotokoll oder vom Betreiber) oder das Konto gesperrt: Jede HTTP-Anfrage wird sofort abgewiesen, eine offene WebSocket-Verbindung spätestens nach dem Prüfintervall geschlossen. Tests in Task 4, 5, 8 und 9.
3. **API-Key neu erzeugt:** Geräte, die sich schon einmal angemeldet haben, melden sich weiter an, auch nach Ablauf der Sitzung; ein neues Gerät und eine neue Registrierung brauchen den neuen Key. Tests in Task 4 und 9.
4. **Mitglied mit Leserecht oder ein Fremder** schreibt einen Datensatz, ändert das Manifest, lädt Umschläge hoch, liest einen fremden Bereich oder löscht ihn: `403 forbidden`, nichts wird geschrieben. Tests in Task 6 und 7.
5. **Übergroße oder kaputte Eingaben** (Körper über 1 MiB, Protokoll mit tausenden Einträgen, zu langer Gerätename, ungültiges Base64, unbekanntes Mitglied, Flut von Challenges): saubere 4xx- oder `503 busy`-Antwort, keine Panik, kein halber Schreibvorgang. Tests in Task 4 bis 7.

**Interfaces:**
- Consumes: Typen aus `sshcraft-proto` (`AccountPublic`, `DeviceCertificate`, `DeviceLog`, `LogEntry`, `AreaId`, `AreaManifest`, `KeyEnvelope`, `SealedRecord`).
- Produces (genau so, Task 3 bis 9 bauen darauf):

```rust
pub struct AccountRow { pub account: AccountPublic, pub name: String, pub email: String, pub created_at: i64, pub locked: bool }
pub struct DeviceRow { pub device_id: Uuid, pub account: AccountPublic, pub cert: DeviceCertificate, pub active: bool, pub admin_blocked: bool, pub has_logged_in: bool, pub last_seen: Option<i64> }
pub struct SessionRow { pub device_id: Uuid, pub account: AccountPublic, pub expires_at: i64 }
pub struct AreaRow { pub owner: AccountPublic, pub manifest: AreaManifest }
pub struct StoredRecord { pub seq: u64, pub record: SealedRecord }
pub struct DeviceChanges { pub added: Vec<DeviceCertificate>, pub revoked: Vec<Uuid> }
pub enum AreaOutcome { TransferTo(AccountPublic), Delete }
pub struct AreaFate { pub area_id: AreaId, pub members: usize, pub outcome: AreaOutcome }

#[derive(Debug, thiserror::Error)]
pub enum StoreError { Conflict { current: u64 }, EmailTaken, AccountExists, DeviceIdTaken, NotFound, Backend(String) }

#[async_trait::async_trait]
pub trait Store: Send + Sync {
    /// Returns the API key, creating one on first use; `true` when it was created now.
    async fn api_key(&self) -> Result<(String, bool), StoreError>;
    async fn rotate_api_key(&self) -> Result<String, StoreError>;

    async fn create_account(&self, row: &AccountRow, email_norm: &str, first: &LogEntry, device: &DeviceCertificate) -> Result<(), StoreError>;
    async fn account(&self, account: &AccountPublic) -> Result<Option<AccountRow>, StoreError>;
    async fn account_by_email(&self, email_norm: &str) -> Result<Option<AccountRow>, StoreError>;
    async fn list_accounts(&self) -> Result<Vec<AccountRow>, StoreError>;
    /// Locking also deletes the account's sessions.
    async fn set_locked(&self, account: &AccountPublic, locked: bool) -> Result<(), StoreError>;

    async fn device_log(&self, account: &AccountPublic) -> Result<DeviceLog, StoreError>;
    /// Appends only if the stored log has exactly `expected_len` entries, else `Conflict { current }`.
    /// Adds `changes.added` as active devices, marks `changes.revoked` inactive and deletes their sessions.
    async fn append_log(&self, account: &AccountPublic, expected_len: u64, entries: &[LogEntry], changes: &DeviceChanges) -> Result<(), StoreError>;
    async fn device(&self, device_id: Uuid) -> Result<Option<DeviceRow>, StoreError>;
    async fn devices_of(&self, account: &AccountPublic) -> Result<Vec<DeviceRow>, StoreError>;
    async fn mark_logged_in(&self, device_id: Uuid, now: i64) -> Result<(), StoreError>;
    async fn touch_device(&self, device_id: Uuid, now: i64) -> Result<(), StoreError>;
    /// Blocking also deletes the device's sessions.
    async fn set_admin_blocked(&self, device_id: Uuid, blocked: bool) -> Result<(), StoreError>;

    async fn create_session(&self, token_hash: [u8; 32], device_id: Uuid, account: &AccountPublic, expires_at: i64) -> Result<(), StoreError>;
    async fn session(&self, token_hash: [u8; 32]) -> Result<Option<SessionRow>, StoreError>;
    async fn delete_expired_sessions(&self, now: i64) -> Result<u64, StoreError>;

    async fn area(&self, area_id: AreaId) -> Result<Option<AreaRow>, StoreError>;
    /// Areas the account owns or is a member of.
    async fn areas_of(&self, account: &AccountPublic) -> Result<Vec<AreaRow>, StoreError>;
    /// Accounts that share at least one area with `account` (owner or member), without itself.
    async fn area_peers(&self, account: &AccountPublic) -> Result<Vec<AccountPublic>, StoreError>;
    /// `expected` = `None` for a new area (version must be 1), else the stored version (new = stored + 1).
    /// Rewrites the member index from `manifest.members`; a higher `key_version` drops older envelopes.
    async fn put_manifest(&self, owner: &AccountPublic, manifest: &AreaManifest, expected: Option<u64>) -> Result<(), StoreError>;
    async fn delete_area(&self, area_id: AreaId) -> Result<(), StoreError>;
    /// Replaces the envelope per (area, device); all must carry the area's current key version.
    async fn put_envelopes(&self, area_id: AreaId, envelopes: &[KeyEnvelope]) -> Result<(), StoreError>;
    async fn envelope_for(&self, area_id: AreaId, device_id: Uuid) -> Result<Option<KeyEnvelope>, StoreError>;

    /// Compare and swap: version 1 for a new record id, else stored + 1. Returns the area-local
    /// change number (`seq`), which grows by one per accepted write in this area.
    async fn put_record(&self, record: &SealedRecord) -> Result<u64, StoreError>;
    async fn records_since(&self, area_id: AreaId, since: u64, limit: u32) -> Result<Vec<StoredRecord>, StoreError>;

    async fn plan_account_deletion(&self, account: &AccountPublic) -> Result<Vec<AreaFate>, StoreError>;
    /// Runs exactly the plan of `plan_account_deletion` in one transaction and returns it.
    async fn delete_account(&self, account: &AccountPublic) -> Result<Vec<AreaFate>, StoreError>;
}

pub async fn open(url: &str) -> Result<Arc<dyn Store>, StoreError>; // "sqlite://<path>" or "postgres://..."
```

- Regeln für `plan_account_deletion` (Spec Abschnitt 12): je Bereich, den das Konto besitzt: hat das Manifest ein Mitglied mit `Role::Write`, geht der Besitz an das erste solche Mitglied in Manifest-Reihenfolge (`TransferTo`), sonst `Delete`. Persönliche Bereiche (ohne Mitglieder) immer `Delete`. Beim Löschen verschwinden außerdem Konto, Protokoll, Geräte, Sitzungen, die Umschläge seiner Geräte und seine Zeilen im Mitglieder-Index fremder Bereiche.
- Schema (SQLite, `PRAGMA user_version = 1`, alles in einer Transaktion, `PRAGMA foreign_keys = ON`, `journal_mode = WAL`): `server_config(key TEXT PK, value TEXT)`, `accounts(account BLOB PK, name, email, email_norm TEXT UNIQUE, created_at, locked)`, `log_entries(account, seq, entry TEXT, PK(account, seq))`, `devices(device_id TEXT PK, account, cert TEXT, active, admin_blocked, has_logged_in, last_seen)`, `sessions(token_hash BLOB PK, device_id, account, expires_at)`, `areas(area_id TEXT PK, owner BLOB, version, key_version, manifest TEXT)`, `area_members(area_id, account, role, PK(area_id, account))`, `envelopes(area_id, device_id, key_version, envelope TEXT, PK(area_id, device_id))`, `records(area_id, record_id, version, seq, record TEXT, PK(area_id, record_id))` mit Index `(area_id, seq)`. Fremdschlüssel mit `ON DELETE CASCADE` von Konto auf Protokoll, Geräte und Sitzungen, von Bereich auf Mitglieder, Umschläge und Datensätze.
- SQLite-Zugriff: eine `rusqlite::Connection` hinter `std::sync::Mutex`, jeder Aufruf in `tokio::task::spawn_blocking`, jede schreibende Methode in einer `IMMEDIATE`-Transaktion. Das macht jedes Compare-and-swap atomar.
- `seq` eines Datensatzes: `COALESCE(MAX(seq), 0) + 1` im Bereich, in derselben Transaktion.
