# SSHCraft Teilplan R3: Terminal Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ein Terminal ohne Toolkit (`crates/term`, L2, auf `alacritty_terminal`) und sein egui-Renderer (`crates/ui-egui/src/terminal/`, L6), angebunden an den `TerminalStream` der Engine mit Flusskontrolle, mit den Escape-Regeln aus Spec Abschnitt 17, Leistungsbudgets als Tests, einem Snapshot-Beispiel ohne Fenster und einem Fenster-Beispiel für die Probe von Hand.

**Architecture:**
- **Zuerst der Wegwerf-Versuch** (Task 1, nicht committet): Durchsatz von `alacritty_terminal`, Zeichenzeit eines vollen Gitters im egui-Fork der Familie, Ligaturen und Graphem-Cluster, Systemschriften, IME. Das Ergebnis entscheidet im Ledger, ob `alacritty_terminal` bleibt, wie Text gezeichnet wird (Läufe oder Zellen) und welches Byte-Budget ein Frame bekommt.
- **`term` kapselt `alacritty_terminal` vollständig.** Nach außen gehen nur eigene Typen (`Screen`, `CellView`, `TermColor`, `Notice`, `Key`), damit Renderer und spätere Oberfläche den Emulator nicht kennen (Spec 15: ein anderer Emulator bleibt möglich). Ein kleiner Vorfilter vor dem Parser setzt die Grenzen durch, die der Parser selbst nicht kennt (überlange OSC-Folgen, Titel-Abfrage).
- **Der Renderer ist zweistufig:** `layout(&Screen, &CellMetrics, &TermPalette) -> Vec<Primitive>` ist rein und wird mit Unit-Tests geprüft, `paint` zeichnet die Primitive mit dem egui-Painter. Bilder kommen nie ins Repository (Spec 7.4); geprüft wird über das Layout und über AccessKit in egui_kittest.
- **Flusskontrolle:** `Pump` liest je Frame höchstens `FRAME_BYTE_BUDGET` Bytes aus dem `TerminalStream`, füttert `term` und bestätigt genau das Verarbeitete mit `ack`. Was übrig bleibt, wartet im `Pump`; die Engine liest den Server erst weiter, wenn bestätigt ist.

**Tech Stack:** Rust 1.99 (Edition 2024), `alacritty_terminal` 0.26.0 (Apache-2.0), egui, eframe und egui_kittest aus dem Fork `storytold/egui` (Rev. `6d518fc799681571963842f95b55a6b68431b15a`) über `[patch.crates-io]` wie in craft-libs, `regex-automata` über `alacritty_terminal` für die Suche, `rand` (vorhanden) für den Fuzz.

**Spec:** `docs/superpowers/specs/2026-11-14-sshcraft-craft-neuaufbau-design.md`, Abschnitte 5, 7.1 (Grundsätze, soweit das Terminal sie braucht), 7.3, 7.4, 8, 13 (Zeile R3), 14 (Terminal-Risiko), 15, 16.1 (Regex-Suche, Ligaturen, Graphem-Cluster, Leistungsbudgets), 17 (Regeln 3, 9, 11).

## Review Focus

1. **Eine OSC-Folge ohne Ende** (Server schickt `ESC ] 52 ; c ;` und dann 100 MiB ohne `BEL`/`ST`): Erwartet: Speicher bleibt begrenzt, kein `ClipboardWrite`, Text danach erscheint normal (Test `an_endless_osc_is_dropped_and_output_goes_on`, Task 3).
2. **Riesige Parameter** (`CSI 4294967295 @`, `CSI 65535;65535 H`, `CSI 999999 S`, `CSI 1000000 b`): Erwartet: kein Absturz, keine Allokation über das Gitter hinaus (Test `huge_csi_parameters_stay_inside_the_grid`, Task 2; dazu der Fuzz).
3. **Eingefügter Text mit eigenem Klammerende** (`ls\x1b[201~rm -rf ~\r`): Erwartet: kommt vollständig innerhalb der Klammer an, nichts davon wird als Eingabe nach der Klammer ausgeführt (Test `pasted_text_cannot_close_the_bracket`, Task 5).
4. **Fenster schneller als der Server ist langsam, Server schneller als das Fenster** (1 GB über `cat`): Erwartet: ein Frame verarbeitet höchstens `FRAME_BYTE_BUDGET`, bestätigt genau das, die Oberfläche bleibt bedienbar (Tests `a_frame_takes_at_most_the_budget_and_acks_what_it_took`, Task 8; `feeding_one_frame_budget_stays_under_8_ms`, Task 8, Release).
5. **Größe 0 oder riesig** (Fenster minimiert, Schrift 8 pt auf 8K): Erwartet: Größe geklemmt auf `MIN_COLS..=MAX_COLS` und `MIN_ROWS..=MAX_ROWS`, Speicher unter `SESSION_MEMORY_BUDGET` (Tests `sizes_are_clamped`, `the_grid_fits_the_memory_budget_at_every_size`, Task 2).
