# SSHCraft Teilplan R2: Engine Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ein neues Crate `crates/engine` (`sshcraft-engine`, Schicht L5) hält alles, was das Tauri-Backend bei `tauri-final` konnte, als Engine-Befehle hinter `Session::execute(caller, id, params)`: Befehlsregister, Agent-Prüfung für jeden Aufruf außer dem des Benutzers, Absturzschutz mit Fuzz-Tests, Sitzungen, Weiterleitungen, Aufzeichnung und Sync im Hintergrund, Ereignisse für die künftige Oberfläche und Einstellungen in `config.toml` über `craft-settings` mit der einmaligen Übernahme der Tauri-Einstellungen.

**Architecture:**
- **Ein Befehl je Aktion.** `crates/engine/src/cmd/<bereich>.rs` liefert `specs()`, `cmd/mod.rs` sammelt sie in einem `OnceLock`-Register wie gridcraft. Weil SSH, Sync und die Rückfrage an Agents warten müssen, ist `run` asynchron und `Session::execute` eine `async fn`; sonst gilt das Muster von gridcraft (`enabled`, `journal`, `catch_unwind` um den Lauf, `every_command_survives_empty_params`, Fuzz über Befehlsfolgen).
- **Die Agent-Prüfung ist Teil von `execute`.** Jede `CommandSpec` trägt `agent: Option<&'static AgentAccess>`: Kategorie, Rückfrageregel, eine Auflösung der Agent-Parameter (verborgene Hosts, Sprung-Hosts, umgelenkte Zugangsdaten) und eine Darstellung des Ergebnisses für Agents. `None` heißt: für Agents und den Control-Channel nie erreichbar. Die Logik zieht aus `app/src-tauri/src/agents/gate.rs` um, die Typen aus `crates/sshcraft-agent/src/lib.rs` (beide bei `tauri-final`).
- **Was dauert, läuft neben den Befehlen:** Terminal-Ausgabe über einen Kanal je Sitzung (`TerminalStream`), alles andere über einen Ereignisbus (`tokio::sync::broadcast`), den die Oberfläche ab R4 abonniert. Rückfragen (Host-Schlüssel, Anmeldung, Agent) haben eine gemeinsame Nummernfolge und lassen sich jederzeit mit `prompt.list` neu abfragen. Ohne Abonnenten (R2 hat kein Fenster) ist jede Agent-Rückfrage ein Nein.

**Tech Stack:** Rust 1.99 (`rust-version = "1.95"`, Edition 2024), tokio, `futures` (`BoxFuture`, `FutureExt::catch_unwind`), `craft-settings` aus `storytold/craft-libs` (Git, gepinnte Revision), `chrono` (Datum im Dateinamen beim Protokoll-Export), dazu aus dem Tauri-Backend `url`, `strum`, `wait-timeout`, `sys-locale`, `winreg` (nur Windows), `data-encoding`.

**Spec:** `docs/superpowers/specs/2026-11-14-sshcraft-craft-neuaufbau-design.md`, Abschnitte 2 (Ziel 3), 5, 6, 8, 9 (soweit die Engine-API sie bedient), 10, 13 (Zeile R2), 17 (Regeln 1, 2 und 6).

## Review Focus

1. **Ein Agent schmuggelt Felder in `host.save`:** etwa `jump_hosts`, `identity`, `password_id`, `agent_forwarding` oder `proxy` neben den erlaubten Feldern. Erwartet: Fehler "field not allowed for agents", nichts gespeichert, Eintrag `Failed` im Agent-Protokoll (Test `agent_host_fields_outside_the_list_are_refused`, Task 7).
2. **Die Oberfläche liest die Ausgabe nicht ab** (Tab nie angehängt, Fenster hängt): Erwartet: Die Sitzung liest den Server nicht weiter, der Speicher bleibt unter `OUTPUT_HIGH_WATERMARK` plus einem Block, die Sitzung läuft nach dem Anhängen weiter (Test `an_unattached_terminal_stays_bounded`, Task 6).
3. **Ein Abonnent des Ereignisbusses fällt zurück** (`RecvError::Lagged`) und verpasst das Ereignis einer Rückfrage. Erwartet: `prompt.list` zeigt jede offene Rückfrage, eine Antwort darauf wirkt (Test `a_lagging_subscriber_still_finds_open_prompts`, Task 6).
4. **`config.toml` von einer neueren Fassung oder beschädigt.** Erwartet: Die Engine öffnet, die Einstellungen sind lesbar, nichts wird überschrieben, keine Übernahme wird vermerkt (Test `newer_config_is_read_only_and_not_overwritten`, Task 3; beschädigte Datei deckt craft-settings selbst ab).
5. **Zwei Prozesse auf denselben Daten:** ein zweites `Session::open` im selben oder einem anderen Prozess, oder die Tauri-Fassung läuft noch. Erwartet: Fehler `DataInUse` beziehungsweise `LegacyRunning`, bevor die Datenbank oder der Tresor geöffnet ist (Tests `a_second_engine_on_the_same_data_is_refused`, `a_running_tauri_version_is_refused`, Task 2).
